Have more than one model read ssa and AGENTS.md.
Each model suggests changes that would improve the
project. Have them check AGENTS.md and POSIX

Add those suggestions as tasks in plan.txt. Leave ssa

2) One setting for what a run may do

Five settings each turn one action off. They
are SSA_NO_EDITS, SSA_NO_MESSAGES,
SSA_NO_QUESTIONS, SSA_NO_SCRIPTS, and
SSA_NO_WRITES. Each must be 0 or 1. Each has
its own check. The log prints all five. The
system prompt adds a reply spec for each
action that is still on. The run stops when
scripts, writes, edits, questions, and
messages are all off.

SSA_NO_ASK is not an action. It skips the
ask before a script, a write, or an edit.
With no /dev/tty, it also turns questions
and messages off. Keep SSA_NO_ASK.

Replace the five with SSA_ALLOWED_ACTIONS.
It is a string of names separated by spaces:
script, write, edit, question, and message.
Unset means all five are on. # complete is
not a name. It still does not keep a run
going by itself.

A name that is not one of those five is a
bad value. The message names
SSA_ALLOWED_ACTIONS. An empty value means
no action is on, so the run stops. That
message names SSA_ALLOWED_ACTIONS too.

The log and README record
SSA_ALLOWED_ACTIONS and SSA_NO_ASK. Drop
the five SSA_NO_* action names. The system
prompt still adds a reply spec for each
name that is on. No /dev/tty still needs
SSA_NO_ASK=1, and still turns questions
and messages off. No action left still
stops the run.

10) Send the user turn in the current shell

call_llama pipes the log slice into
send_user_message. A pipeline subshell resets
the PIPE trap. If llama-cli is already gone,
the write gets SIGPIPE and the subshell dies
before die runs. The loop status is not
checked, so the run continues into the read
and dies there.

Send that turn in the current shell. If the
write fails because llama-cli has exited, die
with the llama-cli message.

11) Do not block forever on the stderr fifo

The stderr reader opens the fifo for read and
waits until a writer opens it. If llama-cli
is killed before it opens stderr, that open
waits forever. wait never returns, and the
fifo directory is left behind.

Open the fifo so the reader does not depend
on llama-cli being the first writer. If
llama-cli dies first, the reader must finish
and the watcher must clean up.

12) Strip the prompt mark before the end line

The first reply line can start with "> ".
The carriage return on "# end" is stripped
before that mark is removed. A first line
"> # end" with a carriage return is logged
with the mark and the return still on it.
Later reads of that line are not exactly
"# end".

Remove the prompt mark first, then strip the
carriage return, and log that line. A first
line that is the end marker must be stored
as "# end".

13) A write or edit path needs a space

The first action line matches "# write file:"
and "# edit file:" with no space after the
colon. The missing-path check only matches a
blank path. "# write file:foo" or a tab
before the path is not a missing path, and
it does not match the write or edit handler.
The reply is reported as having no action
line.

A path must come after one space, as in the
reply spec. Any other shape means the path
is missing. Say that.

14) Check an edit before the ask

An empty search block passes the format
check. The file check, the NUL check, and
the match count run only after the user
approves. The ask runs for an edit that
will fail as soon as it is applied.

Reject an empty search block as a format
error. Before the ask, check that the file
exists, has no NUL, and the search matches
once. Send that failure back without
asking. Apply the edit only after a yes.

15) One blank line before the exit code

A script and a write add a newline after
the output. The action closer adds two more
before "Action exit code:". The log shows
several blank lines there. A command that
prints nothing still leaves blank lines
between the header and the exit code.

Keep a single blank line between the output
and "Action exit code:". Do that when the
output is empty too. Add the newline in one
place.

16) A failed write must not exit the shell

The write opens the target with a redirect
on a function, in the main shell. A POSIX
shell exits on a redirection error. If the
file cannot be opened, ssa can exit instead
of recording the failure and continuing the
loop.

Open the target so a failed open is an
action error. Save that status, log it, and
continue the loop. A failed append to the
log is still a harness failure.

17) die must not signal itself

die sends USR1 to the startup PID. In the
main process that PID is this process. The
USR1 trap exits, so die can be cut off by
its own signal. The signal is there so a
subshell can stop the main process.

Ignore USR1 while die runs. Signal the main
process only from a subshell. In the main
process, finish the log and the fifo
cleanup, then exit 1.

18) Tell the model what a later turn is

The intro says later turns are prior
commands and their output. After the first
turn, each user message is the output or
the error from the last reply. The model
already has that reply.

Say that. Leave the first turn as the
stdin context.

The edit spec says the search block must
match exactly once. The next sentence says
the next line is # end. That sentence sits
after the search block, so the model can
end the reply there.

Say the search block must not be empty and
must match exactly once. Say the line after
the replace marker is # end.

The edit program sends a failure through
cat on stderr. The caller already takes
stderr with stdout. Print the message and
drop the cat.

19) Simplify README and keep it abstract

AGENTS.md says the help stays short: how
to run, the environment, one loop
paragraph, and the exit codes. Copy ssa
only as far as a person needs to run it.

README now names each tool on PATH, the
reply markers, each log field in order,
and the llama-cli flags ssa passes. Those
lines follow the program. They have to
change when ssa changes, and they are
more than a person needs to start a run.

Rewrite README in broader terms. Keep
how to run, the settings, and the exit
codes. Describe the loop and the log in
a few sentences. Leave the marker rules,
the log layout, and the flag list in ssa.
