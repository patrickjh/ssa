1) Ask several models for changes

Have more than one model read ssa and AGENTS.md.
Each model suggests changes that would improve the
project. Have them check AGENTS.md and POSIX
compliance. Have them review the system prompt.

Add those suggestions as tasks in plan.txt. Leave ssa
and AGENTS.md as they are.

2) Log llama-cli errors

watch_llama sends llama-cli stderr to the
stdout this process inherited. With
SSA_VERBOSE=0 that text is dropped. With
SSA_VERBOSE=1 it is printed and not stored.

A load failure then dies with "llama-cli
exited", and the useful text is gone. The
full log needs that text.

Write llama-cli stderr into the log.
SSA_VERBOSE=0 still hides it from the screen.
SSA_VERBOSE=1 can still print it. Update
README.md only if a person would otherwise
not know where that text goes.

3) Stop a short -n from hanging the loop

A finite -n, --predict, or --n-predict can
end generation before a line that is exactly
# end. ssa keeps reading that line.
llama-cli is waiting for the next user turn.
The two sides wait on each other.

Pick one fix: reject that finite limit, pass
-n -1 after the caller flags, or detect the
end of a reply another way. The loop must
not hang. Update the README.md note about a
short -n so it matches the fix.

4) Leave CPU for the rest of the machine

llama-cli can take every generation thread
and poll while it waits. The model load and
the reply can be slow. They should leave
CPU for the rest of the machine.

Pass --prio -1 and --poll 0 with the other
flags ssa puts in front. Leave the thread
count to SSA_LLAMA_CLI_ARGS. Add no new
SSA_* setting. A later caller flag can
still replace one of these. Pass a flag
only when its default does not already do
the job. List the flags in README.md.

5) Record the run in the log

The log does not record the llama-cli version,
the effective arguments, the working directory,
the runtime settings, the start time, the end
time, or the final status. A later read of the
log cannot rebuild the run.

Write the start of the run before the system
prompt. Use llama-cli --version, or llama cli
--version when that is the command ssa runs.
Record the working directory, each SSA_* value
in effect after the startup checks, the flags
ssa passes, and the start time. Use the same
date form as the log file name. The system
prompt is already its own chunk, so do not copy
it again.

When the run ends, record the end time and the
final status. A completed task says it
completed. A die says so and includes the die
text. A hangup, interrupt, or terminate says
which signal ended the run.

Add no SSA_* setting. Update README.md only if
a person would otherwise not know what the log
starts and ends with.

6) Add a read-only file action

A run with scripts, writes, and edits off cannot
look at a file. Add "# read file: PATH". The
file is not changed. Its contents are the action
output, so the next turn can read them.

SSA_NO_READS defaults to 0. It must be 0 or 1.
When it is 1, the reply is a format error. A
missing path is a format error. Text after the
read line, before # end, is a format error. A
missing file, a directory, or a file with a NUL
is a failed action, not a die. Do not cap the
output. A long file can fill the context.

Ask before the read unless SSA_NO_ASK is 1. A
read counts as an action left. Include
SSA_NO_READS in that check.

Say the format in the system prompt when reads
are allowed. Document SSA_NO_READS in README.md.
If ssa would pass 1000 lines, raise that limit
in AGENTS.md in the same change.

7) Let # complete carry a final message

# complete ends the run. A final word now needs
a # message turn, then another turn that is only
# complete.

Let the lines after # complete, and before # end,
be a message for the user. A blank body still
ends the run. A body that is only space is blank.
Show a non-blank body on /dev/tty the same way as
# message, then end the run. Do not ask. Do not
start another model turn.

If SSA_NO_MESSAGES is 1, a non-blank body is a
format error. A blank # complete still ends the
run. A run with no terminal turns messages off,
so the same rule applies there.

The complete line stays its own action. Do not
append it to another action. Text after it is
the message, not another action.

Say this in the system prompt. Update the
README.md loop paragraph so a person knows the
final message is shown and the run ends. Add no
SSA_* setting. If ssa would pass 1000 lines,
raise that limit in AGENTS.md in the same change.
