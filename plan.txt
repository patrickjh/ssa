1) Ask several models for changes

Have more than one model read ssa and AGENTS.md.
Each model suggests changes that would improve the
project. Have them check AGENTS.md and POSIX
compliance. Have them review the system prompt.

Add those suggestions as tasks in plan.txt. Leave ssa
and AGENTS.md as they are while collecting them.

10) Sanitize action output, and skip it when quiet

finish_action_message prints the script output with
no sanitize_output pass. Every other path to the
terminal does sanitize.

When SSA_VERBOSE is 1, sanitize that slice. When
SSA_VERBOSE is 0, stdout is already /dev/null, so
do not run sanitize_output on each reply line or
print the action slice at all. Build the
sanitize_output sed program once at startup so it
does not fork a printf per line.

12) Make ssa, AGENTS.md, and README.md agree

edit_format_is_ok is used as a predicate and also
logs. A predicate stays pure: record the format
error in handle_edit_request, and write the status
at each return. check_llama and check_tty should
follow that too.

OUTPUT_END is set at the top and only used inside
finish_action_message. Drop the top-level copy, or
keep top-level and local state consistent. In
apply_edit_request, the edited-file line does not
need a printf subshell.

watch_llama passes both --reasoning off and
--reasoning-budget 0. Pass a flag only when its
default does not already do the job, or note the
exception in AGENTS.md.

In run_script, the comment "#hold them." needs a
space after #.

README.md says the run ends when scripts, writes,
edits, questions, and messages are all turned off.
check_some_action_left rejects that at startup
with status 1. Say the run ends when the model
completes the task or the user quits, and that at
least one action must stay on.
