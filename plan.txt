2) Ask several models for changes

Do this after the AGENTS.md review. Have more than one

Add those suggestions as tasks in plan.txt. Leave ssa
and AGENTS.md as they are.

3) Double check POSIX compliance

ssa is POSIX sh. Read the script for features that are
bash, ksh, or another shell: arrays, [[ ]], process
substitution, local outside a function, and similar.

Check external utility options too. The log uses sed
line ranges. head -c is not POSIX. Replace any other
non-POSIX use, or document the required GNU or BSD
utility behavior.

Fix what is not portable under the stated requirements.
Leave a construct that is already portable and clear.

4) Review the system prompt

Read the system prompt text in ssa. Cut sentences,
examples, and repeated rules that the model can do
without. Keep a rule the harness still needs it to
follow.

Leave the task line and any SSA_EXTRA_SYSTEM_TEXT
in place. Update README.md only if a setting's
meaning would otherwise be unclear.

5) Figure out how to turn reasoning on

Reasoning is off. ssa passes --reasoning off and
--reasoning-budget 0. AGENTS.md says not to add a
thinking trace the device must generate, and it
lists thinking left on, with the trace stripped
from history, as kept out.

Work out a later change that turns reasoning on
and still reads one action per reply. Do not
change ssa, README.md, or AGENTS.md for this task.
When the approach is clear, add it here as the
next task.

The reply and the trace share one stdout. On
current llama-cli the trace is a prefix, marked
by the lines [Start thinking] and [End thinking].
The reader stops at the first line that is exactly
# end. The first action line in that text is the
action. A trace that contains an action line or
# end is taken as the reply.

ssa does not send the model reply back. llama-cli
keeps the chat, so a trace stays in later turns
unless a llama-cli flag drops it. Context shift
drops old turns and keeps the system prompt.

The system prompt tells the model to put reasoning
in # comments and to use no thinking tags. Any
approach has to say what that text becomes.

Say what happens to the low-token goal and the
kept-out line. Leave both as they are until that
decision is written down.

6) Ring the terminal when an ask is waiting

When the computer is ready for the user, write
the terminal bell (BEL) to /dev/tty. POSIX
printf '\a' is the chime. Do not send it
through sanitize_output. That path turns BEL
into ?.

Ring after the text is written, when the
computer is ready for the user. A person who
looks then can read it. They do not wait for
model output or for the message still to
appear. Do not ring before that text.

Show the action, write the apply prompt, then
ring once. A bad answer does not ring again.
Write the rejection prompt, then ring once,
then read the reason. SSA_NO_ASK=1 never
reaches those reads.

Show the # question text, then ring once, then
read the answer. SSA_NO_QUESTIONS=1 never
reaches that read.

Write the # message body, then ring once. A
message does not wait for a line.
SSA_NO_MESSAGES=1 never reaches that write.

A missing /dev/tty reaches none of these.

Add no SSA_* setting. Muting the bell is a
terminal option. Add one sentence to the loop
section of README.md so a silent terminal is
not mistaken for a hang. Whether a sound plays
depends on that terminal.

7) Stop after repeated format errors

A reply that fails the format checks is sent
back, and the loop continues. With
--context-shift and --keep -1 the context does
not fill, so a model that keeps failing never
stops.

Count format errors in a row inside
record_format_error. Any other reply resets
the count. After 5 in a row, die. Add no
SSA_* setting. The message should say the
reply format failed repeatedly.

8) Strip carriage returns from model lines

Do this in the reader, before the line is
logged and before it is compared to # end. A
line that is # end plus a carriage return must
count as # end. Leave the carriage return out
of the log and out of a script, write, edit,
question, or message body. One place only, so the
slice, the end check, and the action body all
see the same line.

9) Cut comments that restate the code

Read the comments in ssa. Cut one that says
what the next lines already show, or what
README.md already says.

Keep a comment that records a constraint the
code does not show. The redirect order on
llama-cli, a read past # end that would block,
the signals the watcher ignores, and the fds a
script must not hold are that kind.

Leave the file header, the section labels, and
the shellcheck directive. Do not change # lines
inside the reply specs. Those are text the
model reads.
