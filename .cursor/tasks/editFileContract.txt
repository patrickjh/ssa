editFileContract — unique SEARCH/REPLACE as a fourth reply shape

Treat "# edit file:" as a twin of "# write file:". Same detection, same
ask/sandbox, same raw tail, path is $0. Apply with jq inside the sandbox
turn (not in the harness: --sandbox-user may be unable to read the
target file).

Do not add JSON tools or unified diffs (see doNot.txt).

Reply shape
-----------

First action line (leading blanks and # notes skipped):

  # edit file: src/app.c
  <<<<<<< SEARCH
  old bytes, copied exactly
  =======
  new bytes
  >>>>>>> REPLACE

Rules:

- Path runs to end of line and must be non-empty (^# edit file: .).
  Empty "# edit file:" is not an edit; it runs as a script (same as
  tests/writeFileRequest/emptyWritePathRunsAsScript.test.sh).
- One file, one SEARCH/REPLACE pair per reply. Extra blocks or junk
  after >>>>>>> REPLACE (other than a trailing newline) fail the turn.
- Old string must match exactly once. 0 or 2+ matches: do not write;
  print a clear error; leave the file unchanged. Unique-match is the
  safety story; do not replace-first.
- Empty new string deletes that block. Empty old string is invalid
  (do not jq split("")).
- Markers are exact whole lines. Old/new must not contain those three
  lines or the split is ambiguous; fail closed.
- Prefer edit for changing an existing file; write for creating one;
  script for mkdir / inspect / run.
- Success: edited file: PATH
  Failure: edit failed: PATH: ... (matched 0 times, matched N times,
  missing markers, file not found). stdout and messages.json, like a
  failed write.
- split is a substring, not line-oriented. Indentation must match.

Loop wiring (handle_model_response)
-----------------------------------

Insert edit next to write, before fence / think / sh -n:

1. Append assistant
2. # task complete -> stop
3. Blank -> format error
4. Write request -> run
5. Edit request -> run
6. Fence / think / invalid sh -> format error
7. Else run as script

A file that contains ``` or <think> in the payload must still apply.
Writes already skip those checks; edits must too.

first_action_line grep:

  ^# task complete$|^# write file:|^# edit file:|^[^#]

reply_is_edit_request matches ^# edit file: .

Update FORMAT_ERROR_NOT_SHELL, HELP_TEXT, and SYSTEM_PROMPT with one
short few-shot. Do not revive the chunk essay.

Malformed markers (sentinel present, SEARCH/REPLACE missing): failed
run (exit 1, message in the transcript), not a format error. Same
recovery as writeToMissingFolderThenRecover. Format error is only for
"this is not an edit/write/script/done shape."

Ask UI can keep saying Script from model: and show the raw
SEARCH/REPLACE.

How the replace runs
--------------------

run_reply_in_sandboxes calls run_in_configured_sandboxes -c '...'
"$PATH" with latestModelResponse.txt on stdin. Path is $0 in the -c
script. Never interpolate PATH, old, or new into the script text.

Put the -c body in a top-level static string (<=80 columns per line).

Sketch:

1. sed -n '/^# edit file: ./,$p' | sed 1d  — same sentinel-to-end
   trick as write (works when the sentinel is line 1).
2. jq --rawfile the target ($0) and the payload (stdin after sed).
3. Split payload on the three markers; require exactly one of each.
4. ($file | split($old)) length must be 2; result is
   $p[0] + $new + $p[1].
5. Write via a sibling temp + mv onto $0.
6. Print edited file: or edit failed: and exit 1.

JQ_BINARY_FLAG is not exported into the sandbox. Pass it as $1
(-b or empty) so Windows jq does not inject CRLF.

Sandbox contract: --sandbox-command already needs sh-style -c plus
sed for writes; edits also need jq on that command's PATH (and
executable by --sandbox-user if set). Document in -h and AGENTS.md.
Do not add awk. Do not reimplement replace in POSIX sed.

Implementation order
--------------------

1. Detection: sentinel, skip sh -n/fences, stub -c that fails.
   Prove empty-path-is-script and fences-in-payload are not format
   errors.
2. Real jq apply: unique match, success message, atomic replace.
3. Failure messages: 0 matches, 2+ matches, missing file, missing
   markers.
4. Prompt + help + AGENTS.md.
5. Full editFileRequest story; sh tests/runTests.sh (Git bash on
   Windows).

No new flags. No JSON tools. No fence-unwrap.

Pitfalls
--------

- Do not sed the path into the jq program.
- Custom sandbox without jq: edit turns fail the way a missing sed
  would break writes.
- Do not send tools in --request-json.
- Outer markdown fence around the whole reply still format-errors
  (first action line is ```). That is intended; do not unwrap.

JSON vs raw payload
-------------------

Training on JSON tools does not make models good at putting source
inside JSON strings. Write requests and this edit shape keep file
bytes out of JSON. Unique-match failure is a better retry than
"your JSON was invalid."
