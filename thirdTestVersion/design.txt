third test version

This folder is a design for a third trial. The programs
in the repo root, in testVersion, and in
secondTestVersion stay as they are. Put this
folder on PATH to run ssa and ssa-edit.

The program is one file. The default is for small
models, such as Gemma 4 E2B. It asks for one
script, then the person can send feedback so the
model can try to fix that script. -a is the
script loop. -m is one string that is
either a GGUF file or a cloud model name.

Both paths use the same model call: curl to a
chat-completions URL. A local file means this
program starts llama-server, then talks to it. A
model name means it uses SSA_URL and SSA_KEY. The
llama-cli program stays in secondTestVersion.


Speed

The default is fast on low-end hardware, such
as a laptop with 4GB of RAM. A rise in quality
that costs speed stays off. The person turns
it on with a variable or a flag. Reasoning
tokens are that kind of switch: off unless -r
or SSA_REASONING turns them on.


Default

This path is for small models. The aim is to see
if those models can fix a script from feedback.
The other reply shapes are out, and so is the
multi-turn agent loop. -a is that loop.

Show the script, then ask

    Run this script? [Y]es [F]eedback [Q]uit

The answers are y, f, and q. A full word is
not an answer.
The same menu is used with -a. There is no No.
Quit stops the run. -y skips the question and
runs the script. Yes runs it with sh -c, and the
terminal is its standard input. The context on
stdin has already been read. With no terminal,
that run uses /dev/null.

Feedback reads a note from the person. The next
call keeps the task in the system text. The old
script stays the assistant message. The note is
the next user message. The model writes the
script again. The new script is shown, and the
question is asked again. Feedback can repeat.
There is no prompt limit on this path. The
history is sent until it passes SSA_LIMIT.

There is no format-error retry, and no # write,
# edit, # chat, or # complete. The system text
asks for POSIX sh to help with the task. Each
reply is one script, with reasoning in #
comments. It also says to print when that
can finish the task, and to create or change
a file only when the task needs that file.
Writes use quoted heredocs. The task is
the last part of that text. The first user
turn is context. It starts with the operating
system and the current directory. When
ssa-edit is on PATH,
notes on how to call it come next.
Text from stdin follows that, so a pipe can pass
more context. A terminal on stdin still has this
user turn.


-a

-a runs the loop. A reply is a script. There is
no # write and no # chat. A line like that in a
reply is an ordinary comment. The loop watches
for # complete and keeps going for another turn.
# complete alone ends the run. As the last line
of a script, it ends the run when that script
exits 0. -y skips the question and runs the
script. This version has no prompt limit.

A reply that is not valid for the shell is an
invalid script. The program prints

    model generated an invalid script, trying again

and then prints that script. The script stays
the assistant message. The next user message is

    invalid script

and the loop continues. The model sorts it out.

The menu is yes, feedback, or quit. Feedback
sends the note as the next user message and the
loop continues. The script stays the assistant
message. Yes runs the script. It reads
/dev/null. Its output is shown to the person
and goes back to the model, with the exit code,
and the loop continues. Quit stops the run.
The history follows SSA_LIMIT, as on the
default path.

The task stays in the system prompt, including
the print line and the quoted heredoc line.
That prompt also says
the task can take many turns. After a script
runs, the next user message is the output and
the exit code. When the task is done, # complete
is the last line of the script, and the run ends
when that script exits 0.
The first user turn is the same context as on
the default path. An
edit is a call to ssa-edit from a script.


-m

-m sets SSA_MODEL only. There is no
SSA_MODEL_FILE and no SSA_BACKUP_MODEL.

If the string names a file, it is the local model.
The name does not need a slash or a .gguf ending.
A renamed file is still the GGUF. The person
chose that path, so the program does not inspect
the contents. It starts llama-server with
--model, --alias local, --host 127.0.0.1, and
--port, plus --reasoning from SSA_REASONING,
and the request uses the name local. The
server stays up for the whole run, including
every turn under -a, and stops on the way out.

Any string that is not a file is a cloud model
name. SSA_URL is required on that path, and
SSA_KEY is the bearer token when the provider
needs one. There is no probe of SSA_URL. The
file check is the whole switch.

A name that is both a file and a cloud model id
is the local model. A file named local in the
working directory starts the server. A missing
path is a cloud model name.

SSA_PORT is the server port. When it is unset,
the program picks a high port from the process
id, 20000 + (pid % 10000). If /health answers
there, it tries the next port a few times. A set
SSA_PORT is that port. If that port already
answers /health, the run stops. The program
waits SSA_WAIT seconds for /health. The default
is 120. POSIX sh has no $RANDOM, so the pick
uses the process id.

-v, -y, -m, -a, and -r come before the task.
-- ends the flags.


Names

Each setting is SSA_ and one word. SSA_PORT is
the port. SSA_LIMIT is how much text is sent.
SSA_WAIT is the server wait. SSA_LOGS is the log
folder. The default is TMPDIR, or /tmp. -y sets
SSA_YES to 1. -v sets SSA_VERBOSE to 1.
-r sets SSA_REASONING. SSA_URL, SSA_KEY, and
SSA_MODEL already fit. A
root name with more than one word, such as
SSA_SERVER_PORT or SSA_SERVER_WAIT, takes one
word in this trial.


SSA_REASONING

SSA_REASONING is the thinking switch. The
default is 0, which is off. -r sets it to 1,
which is on with no effort word. A word after
-r sets it to that word. off and none are off,
the same as 0. on is on, the same as 1.

Off starts llama-server with --reasoning off,
and the request sends reasoning_effort none.
On starts it with --reasoning on and leaves
reasoning_effort out of the request. Any other
word starts it with --reasoning on and
--reasoning-effort set to that word, and the
request sends that same word. The word is the
effort that model expects, such as low or high.

The next word after -r is the effort when that
word does not start with a dash. -r -m model
do the task is on, with no effort word.
-r high -m model do the task sends high.
When -r is the last flag, the next word is the
effort, so -m model -r do the task takes do
as the effort. Use -r on or -r -- there to
turn thinking on and keep the task.

A cloud model gets the same request field.
That path does not start llama-server.
An empty SSA_REASONING is invalid.

With reasoning on, the server can put the
trace in reasoning_content. This program
reads message content only. The raw response
in the log keeps the trace.


SSA_LIMIT

SSA_LIMIT is the most text sent to the model.
The program counts characters. The default is
400000, about 100k tokens. That stays in the
smart range of a large cloud model, and inside
Gemma 4 E2B. A person raises it for a model
with a longer window.

The system text and the first user turn stay.
Older script and note pairs drop until the send
fits. A single message that is still over the
limit goes out as it is. If the model call
fails, the program exits with that error.


The log and a thinking tag

The JSON log stays on the one-shot path too. A
fence or a thinking tag is not stripped from that
reply. With the server, those tags are inside the
reply text only when the model puts them there.
The root loop already sends a format error for a
thinking tag. The default path does not.


ssa-edit

This folder has its own ssa-edit. There is no
# edit reply. A script calls ssa-edit with the
path as the argument and the search/replace
block on stdin, as a quoted heredoc. That
program uses one awk program. The check and the
edit are that same program. The file must already
exist. The search block must be non-empty and
match exactly once. The system text does
not mention ssa-edit. When ssa-edit is on PATH,
the first user turn includes those details.
A # edit line in a reply is an ordinary comment.
