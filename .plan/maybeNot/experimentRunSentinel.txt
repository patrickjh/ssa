Patch the fork enough to run the idea (details in
maybeNot/runOtherLanguages.txt):

- Closed dispatch: first action line must be `# run RUNNER`,
  `# write file:`, `# edit file:`, or `# complete`. Bare
  scripts are format errors. Payload is everything after
  the sentinel; leading notes are not fed to the runner.
- SSA_RUNNER default `sh`; space-separated names on PATH;
  `command -v` at startup; die if missing, empty, or a
  token contains `/`. The value is the whole list, not
  "sh plus extras."
- Append the live tokens to the system prompt as valid
  `# run` runners. One example (`# run sh`, or the first
  token if sh is not on the list). No extra full Python or
  Node samples.
- `# run RUNNER`: extract the payload, ask, then
  `"$RUNNER" < payload`. Same shape for sh, python3, node,
  and a jail. No `sh -n`. No temp file. No py_compile /
  node --check. Fences and think tags still retry. Invalid
  sh or Python fails when it runs. Ask still shows the
  payload first.
- Write and edit are raw bytes, not a program. Do not pipe
  them at python3 or node. They use a listed `sh` only.

Write/edit gate: `sh` is on SSA_RUNNER if a token is exactly
`sh`. Not `bash`, `dash`, `jail-sh`, or a path. Put the
jail on PATH as `sh` if you want jailed writes and
`# run sh`.

If that token exists: same `-c` sed/cat as today (path as
`$0`, bytes on stdin), but invoke that listed token, not
SSA_SANDBOX_COMMAND and not a fallback PATH `sh`. Ask
first. If you also `cat` the edit target through `sh`, do
it only when that token exists (editReadThroughSandbox.txt).
The fork may keep today's harness jq read plus listed `sh`
for `cat >`. If `sh` is absent, do not jq-read the host
file and then refuse the write.

If `sh` is not on the list (`SSA_RUNNER="python3"`): `# run
python3` still works. `# write file:` / `# edit file:` fail
closed (exit 1, loop continues, file unchanged). Ask still
runs. Do not `die` at startup: a list without `sh` is a
valid caller choice. Do not fall back to an unlisted `sh`
on PATH. Do not
invent python `-c` / node `-e` write adapters. Keep
write/edit in the prompt unless live models keep emitting
them and wasting turns; say so in notes.txt.

Stdin is today's sandbox contract, so a jail listed as
SSA_RUNNER can replace COMMAND on run turns. Do not exec
a temp file instead: wrappers that read stdin like sh
would break. Do not add `-` or extra flags on the runner
word (`python3` / `node` already run a piped script). If
a binary needs a flag, wrap it.

Cost of stdin: no real `__file__` / `__filename`; relative
import/require next to "the file" do not work. When the
model needs a path, write foo.py then `# run sh` with
`python3 foo.py`. One-turn `# run python3` is a
self-contained program on stdin. If live runs need a path,
say so in notes.txt; do not add a temp file in this fork
up front.

Drop SSA_SANDBOX_COMMAND in the fork (setting, check, stdin
to COMMAND, write/edit via COMMAND -c). Run turns are
`"$RUNNER" < payload`. Write/edit `-c` use listed `sh`
when that word exists. Isolation the caller still wants:
put a jail on PATH as `sh` (and/or `python3`), or wrap
the whole experiments/runSentinel/ssa process (container,
sudo -u). Do not restore a second env var in the fork. A
run wrapper must read the program on stdin like sh. A
write/edit wrapper must speak sh `-c`. A runner named
`jail-sh` does not jail writes; list `sh`. SSA_RUNNER="sh
python3" is listed `sh` for writes plus python3 for
`# run`. That is the point of dropping the sandbox layer:
one allowlist of PATH names, not COMMAND plus interpreters.
