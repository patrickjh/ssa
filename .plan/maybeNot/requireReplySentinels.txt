requireReplySentinels — every reply starts with a sentinel

Why:
Dispatch today is leftover-as-script: skip leading # notes, then
# write file:, # edit file:, # complete, or sh -n the rest.
That makes a new kind (see subAgents.txt) a special case next to
the default, and a # note can collide with a spawn. Empty
# write file: (no path) falls through and runs as a script. A
comments-only reply passes sh -n and runs. Undecided. Do not
treat this as required work.

Do:
Decide first. If no: leave script-as-default; do not add an
optional # script next to bare scripts (two ways to write a
script is worse). If yes: one breaking change, not a mix.

Uniform shape:

# notes ignored
# kind[: args]
payload

Kinds stay the current three plus # script (and later kinds if
those tasks land). First action line must be a known sentinel;
anything else is a format error. Payload is everything after that
line, not the whole reply. Leading notes are not part of the
script (today they are, because stdin is the full file).

# script is exact, like # complete. sh -n the payload only.
Empty payload is a format error. Ask can label the kind instead
of always "Script from model."

Cost: scripts are the hot path. Gemma 4 31B (see doNot.txt)
already misses envelopes: JSON tool calls if you send tools,
markdown fences, <think> / <|channel>thought. ssa does not
unwrap those; format-error retry is the recovery. Requiring
# script moves the common path onto a protocol line, which is
closer to those misses than write/edit already are. Keep one
system-prompt example that is exactly # script plus a tiny
script. Do not also accept a bare script. Do not rename
write/edit in the same change.

A forgotten # script on an otherwise valid shell reply is the
same as today's prose/fence miss: not run, no ask, no sandbox,
format error in messages.json, next prompt can add the
sentinel. Extra turns, tokens, and context. It can burn
--max-model-prompts (exit 1) if it never complies, same as
fences. A wrong sentinel (# complete as a comment, # script
then a write payload) dispatches; it does not retry. Bare
valid scripts that run today stop until the prefix appears.
# script does not fix fences: a fenced reply still fails.

A fifth kind (# subagent) is more like a second edit shape,
which doNot.txt already rules out for this model.

Related: completeSentinel.txt (maybe # complete; that rename
is not the Gemma-sensitive part). subAgents.txt is cheaper if
script is not the leftover, but that task stays separate.
runOtherLanguages.txt: if that is yes, use `# run` plus
SSA_RUNNER (default sh) here instead of `# script`. Do not
land `# script` and rename it in the next job.
experimentRunSentinel.txt tries `# run` in experiments/
first; do not treat a successful fork as this product
change.

System prompt and the one FORMAT_ERROR string must list the
sentinels (oneFormatError.txt). first_action_line only keeps
known sentinels (drop ^[^#]).

Size:
0 in `ssa` if you keep script-as-default. If yes: about 50 lines to
change (40–70), including SYSTEM_PROMPT, FORMAT_ERROR_*,
first_action_line, payload extract + temp file, sh -n and sandbox
stdin on the bytes after `# script`. Ask kind labels add ~5–15.
Many existing dispatch lines are edits, not only appends. Tests and
AGENTS.md are extra, not in that count.

Tests:
If no: none. If yes: every canned script reply gets # script.
emptyWritePathRunsAsScript becomes a format error.
trailingDoneCommentIsNotDone still runs (done line is in the
payload). Cover empty # script, notes then # script, and that
notes before # script are not fed to sh. Fake curl, --no-ask.
