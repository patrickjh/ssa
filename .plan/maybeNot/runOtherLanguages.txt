runOtherLanguages — run model code as python or node, not only sh

Why:
ssa is a shell agent: leftover-as-script, `sh -n`, stdin to
SSA_SANDBOX_COMMAND (default sh), and a system prompt that only
shows POSIX sh. Write and edit still need sh-style -c plus sed or
cat, so pointing the sandbox at python or node breaks those turns.
You cannot make this a Python agent today without forking the
prompt, dropping `sh -n`, and keeping sh for writes.

The Unix path already works: `# write file: foo.py`, then a
shell turn `python3 foo.py`. A quoted heredoc is one turn but
reintroduces quoting. Polyglot in the harness is only worth it
for one turn, no file, no quoting — the same reason write
exists. Undecided. Do not treat this as required work.

Default stays shell: SSA_RUNNER=sh. Callers opt in with a
list of PATH names (`SSA_RUNNER="sh python3 node"`). That
is a setting, not a hardcoded language table. Still a
product change when the list is not only sh (the model
may emit `# run python3`).

Do:
Decide first.

If no: keep only shell. Do not add SSA_RUNNER, `# python3` /
`# node` / `# run` next to leftover-as-script (two ways to run
is worse). The two-turn write-then-`python3 foo.py` path stays.
Do not change SSA_SANDBOX_COMMAND to mean "scripts are Python";
writes still need sh.

If yes: closed dispatch first (see requireReplySentinels.txt).
Do not keep leftover-as-script for sh and add sentinels only
for other languages. One breaking change, not a mix. If
requireReplySentinels has not landed, land it here as `# run`
plus a runner word rather than `# script` then rename. Do not
do two prompt breaks. Do not also accept a bare script.

Uniform run kind, allowlisted word — not N sibling kinds:

# notes ignored
# run RUNNER
payload

# write file: PATH
# edit file: PATH
# complete

RUNNER is an exact token from SSA_RUNNER. `# run sh` is exact
like `# complete` (the kind plus the word). Unknown `# run ruby`
is a format error. `# run` with no word is a format error.
Empty payload is a format error. Match by string equality
against the parsed list, not a regex of the joined value.

Do not make `# sh`, `# python3`, and `# node` their own kinds
next to write and complete. That grows the kind table and the
prompt; adding a runner is one SSA_RUNNER word, not a new
response type. `# python3 is not installed` as a reasoning
note is a footgun unless the match is exact `$`. `# run
python3` collides less.

SSA_RUNNER — space-separated allow list (default `sh`).

Users can set. Alphabetize with the other SSA_ names
(after SSA_REQUEST_JSON). One PATH name per word
(`python3`, `node`, `sh`). Look up with `command -v`. No
paths (`/usr/bin/python3`, `./venv/bin/python3`): a token
that contains `/` is a usage error at startup, name
SSA_RUNNER. A venv or jail belongs on PATH under that
name. No flags (`python3 -u` is two words). Consecutive
whitespace collapses (`set -- $SSA_RUNNER` with default
IFS).

Unset or omitted: `sh`. The value is the whole list, not
"sh plus extras." `SSA_RUNNER="node python3"` does not
include sh; callers who want shell too write
`SSA_RUNNER="sh node python3"`. Dropping sh from the list
drops write and edit: those turns use a listed `sh` only
(see below). Empty SSA_RUNNER (or only whitespace) is a
usage error: die, name the env var, `; see ssa -h for
help`. Duplicate words: die or keep first; pick one and
test it. Do not treat a comma-separated list as
separators.

At startup, every word must be `command -v` (same as
check_sandbox_command). Missing runner: die before the
loop, name SSA_RUNNER, show the missing word. Do not wait
for a `# run` turn. Do not `die` later if the binary
vanishes mid-run; that turn fails like any script (exit 1,
loop continues). Do not require `sh` on the list at
startup; a Python-only list is a valid caller choice
(write/edit then fail at the turn). Do not require
python3 or node unless they appear in SSA_RUNNER.

The model may only name a listed runner. That is the
allowlist; do not also parse a shebang. Putting `sudo` on
the list is the caller's choice, same as a dangerous
COMMAND today. Do not sniff "is this an interpreter." Do
not add a hardcoded python/node table behind the env var.

Document SSA_RUNNER in -h (space-separated PATH names,
must exist, default sh, no paths). Meaning is unclear
without that sentence. Settings table in AGENTS.md. No
flag; env only.

System prompt: keep the static `# run` example from
substitution. After parse, append the live list as valid
runners for `# run` (the tokens, not extra full response
types). Do not bake python3/node into the static
SYSTEM_PROMPT "for later." If sh is not on the list, do
not leave a `# run sh` example that would format-error;
use the first token for the one example, or build that
example after parse. Gemma 4 31B concatenates examples
(mixedReplyKinds.txt); a one-line list is cheaper than
one sample program per runner. The one FORMAT_ERROR string
lists `# run NAME` (oneFormatError.txt). Do not name
SSA_RUNNER in it; live tokens stay on the system prompt.

Feed every run payload on stdin: `"$RUNNER" < payload`.
Same shape as today's COMMAND. experimentRunSentinel.txt
tries this in a fork (no `sh -n`, no temp file). Do not
add `-` or extra flags on the runner word. Cost: no
`__file__` / `__filename`; the two-turn write then
`python3 foo.py` path still exists. Leading notes are
not part of the payload. Ask can label the turn from the
runner word instead of always "Script from model."

Write and edit are raw bytes, not a program. Do not pipe
them at python3 or node. Do not invent python `-c` /
node `-e` write adapters. Paths stay positional `$0`, no
interpolation.

`sh` is on the list if a token is exactly `sh`. Not
`bash`, `dash`, `jail-sh`, or a path. If that word
exists: same `-c` sed/cat as today, invoke listed `sh`
(`command -v sh`; jail-on-PATH-as-`sh` sees writes). Ask
first. Edit read through that `sh` only if you close
editReadThroughSandbox.txt; otherwise harness jq read
plus listed `sh` for `cat >`. If `sh` is absent, fail the
write/edit turn immediately (exit 1, file unchanged, loop
continues). Do not jq-read then refuse. Do not fall back
to an unlisted PATH `sh`. Do not `die` at startup for a
list without `sh`.

Sandbox: experimentRunSentinel.txt drops COMMAND in the
fork so a jail can be listed `sh` (stdin for `# run sh`,
`-c` for write/edit). If this lands in ssa, do not keep
stdin-to-COMMAND and also stdin-to-RUNNER. Hung scripts
are still not killed.

Rejected: shebang as the protocol. A shebang names an
interpreter. Write, edit, and complete are harness
operations. `#!/write PATH` is `# write file:` with a
fake kernel line; paths with spaces and leading `#`
notes both fight real shebang rules (`#!` at byte 0,
interpreter plus one arg). Models copy real shebangs;
they do not copy `#!/write`. `first_action_line` today
skips `#!/usr/bin/env python3` as a `#` note; feeding
stdin to a fixed command never switches interpreters.
Do not exec an arbitrary model-chosen binary. A real
shebang may appear inside a `# run python3` payload as
bytes; do not also parse it.

Cost: scripts are the hot path. Requiring `# run sh`
has the same Gemma miss as `# script`
(requireReplySentinels.txt): forgotten sentinel is a
format-error retry; wrong sentinel dispatches and does
not retry; can burn SSA_MAX_MODEL_PROMPTS. Extra names
in the appended list are mix risk if you also paste
full examples. A fifth kind (`# subagent`) is still a
separate task (doNot.txt).

Related: experimentRunSentinel.txt (try # run and dropping
COMMAND in experiments/ before deciding this).

(closed dispatch; prefer `# run` plus SSA_RUNNER over
`# script` if this is yes). dropSandbox.txt (always sh vs

Size:
