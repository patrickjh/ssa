runOtherLanguages — run model code as python or node, not only sh

Why:
ssa is a shell agent: required `# script`, `sh -n` on the
payload, stdin to SSA_SANDBOX_COMMAND (default sh), and a
system prompt that only shows POSIX sh. Write and edit are
harness I/O (writeEditInHarness.txt); they do not need the
interpreter to be sh. You cannot make this a Python agent
today without forking the prompt and dropping `sh -n`.

The Unix path already works: `# write file: foo.py`, then a
shell turn `python3 foo.py`. A quoted heredoc is one turn but
reintroduces quoting. A harness interpreter is only worth it
for one turn, no file, no quoting — the same reason write
exists. Undecided. Do not treat this as required work.

One interpreter per run, not a menu. SSA_INTERPRETER
defaults to `sh`. Callers opt in with one PATH name
(`SSA_INTERPRETER=python3`). That is a whole-run language,
not a per-turn pick. Mixing shell and Python in one loop
stays the two-turn Unix path (write then `python3 foo.py`
while the interpreter is `sh`), or a second ssa with a
different interpreter.

Do:
Decide first.

If no: keep only shell. Do not add SSA_INTERPRETER,
SSA_RUNNER, `# python3` / `# node` / `# run` next to
`# script` (two ways to run is worse). The two-turn
write-then-`python3 foo.py` path stays. Do not change
SSA_SANDBOX_COMMAND to mean "scripts are Python"; writes
are harness I/O, not a reason to keep COMMAND as sh.

If yes: one PATH name. Default `sh`. Users can set.
Alphabetize with the other SSA_ names (after
SSA_CONTEXT). Look up with `command -v`. No paths
(`/usr/bin/python3`, `./venv/bin/python3`): a value that
contains `/` is a usage error at startup, name
SSA_INTERPRETER. A venv belongs on PATH under that name.
No flags (`python3 -u` is two words; this setting is one
word). Empty or only whitespace: usage error; die, name
the env var, `; see ssa -h for help`. Unset or omitted:
`sh`. Extra words after the first: usage error (this is
not a list).

At startup, `command -v` that one name (same as
check_sandbox_command). Missing: die before the loop,
name SSA_INTERPRETER, show the word. Do not wait for a
script turn. Do not `die` later if the binary vanishes
mid-run; that turn fails like any script (exit 1, loop
continues). Do not require python3 or node unless they
are the value.

The model does not name the binary. `# script` is
enough. Do not add `# run RUNNER`, `# run python3`, or
an allowlist. Do not parse a shebang. Do not add a
hardcoded python/node table behind the env var. Putting
`sudo` as the interpreter is the caller's choice, same
as a dangerous COMMAND today.

Do not keep bare scripts for sh and a sentinel only for other
languages. Do not also accept a bare script. Do not
rename `# script` to `# run`.

System prompt: substitute the live interpreter word
into the prompt file (the value, not the env var name).
Default example stays POSIX sh (`# script` then `ls
-la`). If the value is not `sh`, do not leave a shell
example that would be wrong for that run; one tiny
example for that interpreter. Do not bake python3/node
into the static SYSTEM_PROMPT "for later." Shared
REPLY_SPEC lists `# script`. Do not name
SSA_INTERPRETER in it; the live word stays on the
system prompt. Do not interpolate into that shared spec
on the error turn (do not name env vars).

Skip `sh -n` when the interpreter is not exactly `sh`.
Feed every script payload on stdin:
`"$SSA_INTERPRETER" < payload`. Same shape as today's
COMMAND. Do not add `-` or extra flags. Cost: no
`__file__` / `__filename`; the two-turn write then
`python3 foo.py` path still exists when the interpreter
is `sh`. Leading notes are not part of the payload.

Write and edit are raw bytes, not a program. Do not
pipe them at python3 or node. Do not invent python `-c`
/ node `-e` write adapters. They run in the harness
(writeEditInHarness.txt; land that first if it is still
open): path as `$1`, no interpolation. Ask still runs.
They work whether the interpreter is `sh` or `python3`.
Do not fail those turns when it is not `sh`. Do not
fall back to PATH `sh`. Do not keep a hidden `sh` for
those turns. Callers who do not want those sentinels
use SSA_NO_WRITES / SSA_NO_EDITS (noWrites.txt /
noEdits.txt). Do not use those knobs as the python
story. Do not `die` at startup for a non-sh
interpreter; a Python-only run is a valid caller
choice.

Do not reuse this knob for jails. SSA_SANDBOX_COMMAND
is isolation (timeout, pledge, sudo -u).
SSA_INTERPRETER is the language of model programs.
dropSandbox.txt wants isolation around the whole ssa
process. A timeout wrapper around sh is not an
interpreter. If COMMAND is still there, do not keep
stdin-to-COMMAND and also stdin-to-INTERPRETER; script
turns use the interpreter. Hung scripts are still not
killed.

Rejected: a space-separated SSA_RUNNER allowlist and
`# run RUNNER`. That exists so the model can pick sh vs
python3 each turn. Extra names in the prompt are mix
risk (mixedReplyKinds.txt). Parse, unknown-runner
format errors, first-token example swap, and a "valid
runners:" append all go away with one word. Mixing in
one session is not this job. Do not copy a `# run` /
SSA_RUNNER menu into ssa.

Rejected: shebang as the protocol. A shebang names an
interpreter. Write, edit, and complete are harness
operations. `#!/write PATH` is `# write file:` with a
fake kernel line; paths with spaces and leading `#`
notes both fight real shebang rules (`#!` at byte 0,
interpreter plus one arg). Models copy real shebangs;
they do not copy `#!/write`. `first_action_line` today
skips `#!/usr/bin/env python3` as a `#` note. Do not
exec an arbitrary model-chosen binary. A real shebang
may appear inside a `# script` payload as bytes; do
not also parse it.

Cost: `# script` on the hot path has the same Gemma
miss as a forgotten fence (mixedReplyKinds.txt):
forgotten sentinel is a format-error retry; wrong
sentinel dispatches and does not retry; can burn
SSA_MAX_MODEL_PROMPTS. A fifth kind (`# subagent`) is
still a separate task (doNot.txt).

Document SSA_INTERPRETER in -h (one PATH name, must
exist, default sh, no paths). Meaning is unclear without
that sentence. Settings table in AGENTS.md. No flag;
env only.

Related: mixedReplyKinds.txt (forgotten `# script`; a menu
of runners is extra mix risk). Keep `# script`; do not
rename. dropSandbox.txt (always sh
vs exec python3; isolation is not this knob).
subAgents.txt (do not add a fifth kind here).
doNot.txt (no JSON tools, no second edit shape).
writeEditInHarness.txt (write/edit stay harness I/O).
noWrites.txt / noEdits.txt (optional; not the python
story). editReadThroughSandbox.txt (edit read through
`sh` only when the interpreter is `sh`).
securityModel.txt (untrusted model, ask then run).
Nested ssa inherits SSA_INTERPRETER if it stays in the
environment (do not unset it for scripts unless a later
auth task says to).

Size:
0 in `ssa` if you keep only shell. If yes, on top of
`# script`: about 20–40 more (SSA_INTERPRETER default
and `command -v`, skip `sh -n` when not sh, prompt
substitution, stdin to interpreter, -h). Tests, AGENTS.md,
and README are extra, not in that count.

Tests:
If no: none. If yes: fake curl, SSA_NO_ASK=1. Default
(unset) is sh: python3 on PATH is unused; `# script`
then sh still runs. Every canned script reply stays
`# script` (not `# run sh`). SSA_INTERPRETER=python3
with a stub on PATH: payload on stdin is the program,
not the whole reply. SSA_INTERPRETER=/path/to/stub
(or any value with `/`) dies at startup. Missing
binary dies at startup (name the env var). Empty
SSA_INTERPRETER dies. Two words die. Empty `# script`
payload format-errors. Notes before `# script` are not
fed to the interpreter. Write/edit still work when the
value is `sh` or `python3` (harness I/O).
SSA_NO_WRITES / SSA_NO_EDITS are separate jobs.
showHelp mentions SSA_INTERPRETER. Do not require a
real python3/node for the default-sh stories.
