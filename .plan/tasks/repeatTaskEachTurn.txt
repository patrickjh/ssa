repeatTaskEachTurn — suffix the argv task on each user turn

Why:
Task drift after a few turns is recency: the last user turn
is a big "Output from running the script" blob and exit
code. Pinning the task in system (taskInSystemPrompt) is
primacy only. A short Task: line at the end of that user
turn sits next to "what do I do now." Do not repeat stdin
or the full context; that would copy the pipe every prompt.

Do:
Land after taskInSystemPrompt (system already has the job;
this is the recency reminder). Repeat the job at the bottom
of each user turn as the last thing: Task: and the argv
bytes (same task.txt), after output and the exit code line.
Same last-line suffix on the first user turn (context /
placeholder) and on format-error user turns so a retry
still sees the job. Put it after the output, not before: a
prefix dies under a huge blob in the same message.

Do not suffix the review_work user ask (that is plain-text
feedback, not another script turn). Do not add a new env var
or -h sentence. Do not repeat context bytes.

If system-only already stops the drift in a live smoke, you
may drop this job and delete the stem; do not ship both
reminders without checking the extra tokens help.

Size:
About 8–15 in ssa (append_script_result, record_format_error
or the shared user-turn writer). Tests extra.

Tests:
Fake curl, SSA_NO_ASK=1. Each user turn in the loop ends
with Task: and the argv text as the last thing (first
user turn, after Script exit code, format-error). Huge
script output still completes; the suffix is still last.
Review user turn lacks Task:. several large turns: early
markers stay, latest user turn still ends with Task:.
Do not require a tty.
