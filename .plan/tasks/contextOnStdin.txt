contextOnStdin — stdin is context; drop SSA_CONTEXT

Why:
SSA_CONTEXT is one file path on the first user turn after
Context:. Several files means the caller cats into a temp
file. Stdin is unused when the task is already on argv, and
the documented fallback (empty argv, task from a pipe) is
not a path anyone here uses. Unix split: what to do on argv,
extra bytes on stdin, ask on /dev/tty. A second channel
(SSA_CONTEXT=file) on top of that is two ways to pass the
same bytes. Agent wrappers then compose with cat:

  cat context/shared.txt context/review.txt | exec ssa "$@"

Do:
Argv is the task (including --). Empty argv is a usage
error even if a pipe is open; do not read the task from
stdin. Die with the task missing; name CLI, not stdin;
`; see ssa -h for help`.

If stdin is a tty, there is no extra context (no Context:
block). If it is not a tty, read it into the existing
context.txt and keep the same first user turn as today
(task, then Context:, then those bytes). Empty stdin
(/dev/null, empty pipe) is empty bytes: no Context: block,
same jq rule as an empty SSA_CONTEXT. Do not read a tty
as notes.

NUL / invalid UTF-8 in the stdin bytes still dies before
the loop (same as a bad context file). Huge stdin still
loads on that first user turn. Ask stays on /dev/tty so
`cat notes | ssa do the thing` still prompts.

Drop SSA_CONTEXT: the env var, -h line, settings table,
file checks (missing, directory, -), and log_context copy
from a path. Missing or directory files are the shell's
job on a redirect. Do not keep SSA_CONTEXT beside stdin.
Do not add SSA_CONTEXT=- as a shim. Do not add a list of
paths. Do not put cat recipes in -h; one sentence that a
non-tty stdin is extra user context. README may show
`cat a b | ssa task` and `ssa "$(cat task.txt)"` for a
task file (quote it; trailing newlines from $(cat) are
fine). ARG_MAX is the caller's problem for a huge task.

Size:
About 20–40 in ssa, likely net fewer (drop the env var and
file checks; stdin read replaces them). -h, README, and
AGENTS.md extra.

Tests:
Fake curl, SSA_NO_ASK=1. run_ssa already uses </dev/null;
those stories stay "task only." Rewrite tests/loadContext
to feed bytes on stdin (pipe or redirect), not SSA_CONTEXT=.
Keep: context after the task, huge stdin still in messages[1],
context still there after large later turns, empty stdin has
no Context: block, NUL in stdin is fatal. Drop dash / missing
file / directory cases (or one case that empty argv plus a
pipe is "task not found"). taskFromStdin becomes that usage
error, or a story that piped bytes land after Context: when
argv has a task. showHelp must lack SSA_CONTEXT and still
explain stdin. Do not require a tty.
