slidingContextWindow — drop old middle turns in the POST

Why:
messages.json grows without bound. Large script output is
POSTed on later turns; the provider (or jq) rejects a body
that is too big. Keep the task at the start and recent
turns at the end. When the request is over budget, drop
the oldest turns after that prefix from what curl sends.
Do not trim messages.json or promptN/ copies.

Do:
Window in build_curl_json_request (jq on the messages
array written into body.json). Leave append_json_message
and the on-disk log unchanged.

Pin always: the system turn and the first user turn
(task, plus Context: when stdin was not a tty). Optionally
also pin the prompt0 bootstrap pair (assistant # script
then its user result) so that is a second kept user turn.
Pick one pin and keep it; do not make it a setting.

Drop complete role pairs (assistant then user, or user
then assistant) from the oldest unpinned messages until
the request is under budget, or until only pin + newest
turns remain. Keep the latest user turn. Do not leave
two assistants or two users in a row.

Budget is bytes of message content (sum of .content
lengths), not tokens and not a turn count.
SSA_MAX_MODEL_PROMPTS already caps how many model
prompts run. Default 0 means no window (today's
behavior). Invalid values die like other SSA_* ints.
One -h sentence. AGENTS.md: log stays full; body.json
may omit middle turns.

If one recent turn is itself over budget, still send
pin + that turn; do not truncate its bytes and do not
invent a second omit path. Existing NUL/UTF-8 omit
stays as-is.

Do not insert a synthetic "N turns omitted" message
unless a live smoke shows the model breaking without
it. Do not window by mutating messages.json. Do not
change review_work except that its POST uses the same
window helper. Do not add a tokenizer.

Related: largeTranscript (log still keeps every
marker). subAgents.txt is a different answer (fresh
child transcript). repeatTaskEachTurn is maybeNot;
do not land a Task: suffix here to paper over drops.

Size:
About 25–40 in ssa (window jq, one helper called from
build_curl_json_request, setting + -h). Tests extra.

Tests:
Fake curl, SSA_NO_ASK=1. Inspect promptN/body.json, not
only messages.json.
- Default 0: several large turns still POST every
  marker (largeTranscript still true for the body).
- Small budget: first user turn (task) and latest
  result stay in body.json; an early unique marker is
  gone from the body but still in promptN/messages.json.
- Pin stays first: body messages[0] system, [1] the
  task user turn.
- Roles still alternate after a drop.
- Review POST is also windowed.
- Invalid SSA_MAX_CONTEXT_BYTES dies.
Do not require a tty.
