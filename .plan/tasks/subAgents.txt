subAgents — figure out how nested agents should work

Why:
Large tasks want a fresh messages.json and a short result back,
without dumping the child's whole loop into the parent. The model
cannot honestly re-enter ssa today: SSA_KEY is unset so
scripts never see it; SSA_URL / SSA_MODEL are unexported
harness locals; inner ssa defaults to ask-on and wants /dev/tty;
child stdout is every inner script's output, which can blow
MAX_MESSAGES_BYTES. This is undecided. Do not treat a fifth reply
shape as required work.

Do:
Decide first. Keep the product Unix-shaped: only shell, each action
a fresh process, no extra protocol unless quoting or a short
result back force it. Document the choice in AGENTS.md; keep -h
short.

The preferred way is to let an agent call ssa: write a prompt
file, then run ssa --no-ask as a script. That matches "do not add
what the caller's shell can do" and avoids a fifth reply shape.

Auth can stay simple: leave the key and URL in the environment so
the child is just another ssa. People who do not want sk-… in
the sandbox point SSA_URL at a local reverse proxy and set
SSA_KEY to a dummy value (see proxyDocs.txt). The proxy
holds the real token; parent and child both POST there. Nested
ssa does not need a wrapper or harness re-exec for credentials.
If the real key is what is exported, the model can curl with it
too; that is the caller's choice. Same-user /proc and config
files can still reveal a key the proxy process holds; a dummy
plus a proxy on another user or host is the tight version.

Stop unsetting SSA_KEY so the dummy is still there for the child. Do not add a
second secret name just for nested runs.

Figure out (auth is not these; they still block a simple nested
ssa even with dummy+proxy):

- Child stdout: the inner loop's script output is the parent's
  next user turn and can blow MAX_MESSAGES_BYTES. Prompt
  convention, a result file, the omit path, or something else.
  Undecided.
- Child ask: inner ssa defaults to ask-on and wants /dev/tty.
  Nested scripts need --no-ask / SSA_NO_ASK=1. Who passes that
  (the model, a wrapper, or the parent exports it)? Nested
  --no-ask also means the child's scripts skip ask.
- Flag-started parents: CLI-set SSA_URL / SSA_MODEL /
  SSA_NO_ASK are harness locals and do not reach the child.
  Env-started parents already pass them through. Export those
  into the sandbox, require env for nested ssa, or drop flags
  (envOnlySettings.txt). Undecided.

One other possibility is a harness flow like write/edit:

# subagent
<raw prompt>

First action line is the sentinel; everything after it is the task,
no quoting. Skip sh -n, fences, and think tags (the prompt may
contain those). Empty tail fails the turn, like a bad edit, and
does not spawn. Optional: # subagent: short label for the ask
banner and promptN/ logs, so a bare # comment is not a spawn.
Ask once on the prompt, then run the child with --no-ask. Child
inherits model, URL, key, and request JSON (and sandbox unless
dropSandbox.txt has landed); fresh temp
and messages.json. Depth 1 (child # subagent fails). Cap the
child's --max-model-prompts. Return child's stdout plus the final
status / exit code as one user turn, not the child's
messages.json; reuse the omit path for huge or NUL output. One
spawn per reply. No parallel, no per-child model.

The spawn syntax is the easy part of `# subagent`. The decision for
that shape is ask, depth, budget, and what the parent sees. Prefer
letting a script call ssa. Credentials do not force a new kind:
dummy key plus proxy (proxyDocs.txt) is enough. The figure-out
list (noisy child, ask, flag-started parents) still might.

Size:
Preferred (agent can call ssa): about 0–15 if you only stop
unsetting the key, document dummy+proxy, and env-started
parents already pass URL and model. A bit more if flag-started
parents must export URL / model / no-ask into the sandbox.
Harness re-exec for auth is not the goal. A `# subagent` shape
like write/edit: about 110 (80–150), including depth 1, child
max prompts, ask-once, stdout+status back. Tests and AGENTS.md
are extra, not in that count.

Tests:
None until a shape is chosen. Fake curl, --no-ask, skip sudo/doas
and real /dev/tty. If an agent can call ssa: a nested --no-ask
run with canned replies returns a short result; dummy
SSA_KEY and SSA_URL in the environment are
enough. Do not require the key to be absent from the child
env. If `# subagent`: cover empty prompt / failed spawn, depth
1, and that the parent user turn is a short result (not the
child's full transcript). Ask-once needs a pty if you keep ask
on for the parent spawn.
