mixedReplyKinds — one reply, one kind

Why:
Gemma 4 31B (ssaWithReview runs) often concatenates two system-prompt
examples into one reply: a # write file: PATH block and a # comment:
script block. The prompt already says one of four shapes and "Do not
put a script after the write file line." First-wins still treats that
as a write: everything after the sentinel is file bytes, so the
script never runs and the file is polluted. Ask can catch it; --no-ask
cannot. Reverse mix (script line then a write sentinel) runs as a
script; the write is a shell comment. Same class as a trailing
# task complete in a script (trailingDoneCommentIsNotDone). Undecided.
Do not treat this as required work.

Do:
Prefer a clearer SYSTEM_PROMPT so the model emits one shape. The
"# comment:" example next to "# write file:" is the copy source;
Gemma treats both as headers to include. Try that first: drop or
rename the labeled "# comment:" line, keep "Put reasoning in #
comments", make "exactly one shape per reply" hard to miss, maybe
shorter examples. Do not grow the prompt into an essay. Smoke with
Gemma 4 31B before adding harness rules. If the prompt change is
enough, stop there.

Harness detection is the fallback, not the goal. A write/edit
payload is raw bytes: a file may contain "# comment:", "ls -la",
or even "# write file:". A grep for a second kind in the tail will
false positive. Do not add a second optional script sentinel (see
requireReplySentinels.txt).

If the prompt is not enough, pick one closed rule, not a heuristic
"looks like a script":

- Format-error when two known action sentinels appear
  (# write file:, # edit file:, # task complete, and # script if
  that task lands) anywhere in the reply. Cheap. Misses
  "# write file:" plus a bare ls with only "# comment:" notes,
  because "# comment:" is not an action sentinel.
- Format-error when the payload after a write/edit contains another
  action sentinel. Same miss. False positive if the file should
  contain that line.

Do not split one reply into two turns. Do not unwrap or run both.
Wrong-kind dispatch without retry is the same warning as
requireReplySentinels.txt. Land after or with that task if # script
becomes a kind; the mix exists today without it.

Related: requireReplySentinels.txt (missing/wrong sentinel).
completeSentinel.txt (done line as a second kind). doNot.txt
(Gemma envelopes).

Size:
Prompt-only: a few lines in SYSTEM_PROMPT (keep -h short; this is
not help text). 0 harness. Format-error on a second action
sentinel: about 10–20 (predicate, FORMAT_ERROR_* line,
handle_model_response before write/edit run). Tests and AGENTS.md
extra.

Tests:
Prompt-only: none unless canned replies copied "# comment:" and
that example goes away. If a harness rule lands: fake curl,
--no-ask. Write then "# comment:" / ls is a format error or a
polluted write, matching the decision. Two writes, write then
# task complete, edit then a script sentinel. A write whose file
bytes are exactly "# comment:\nls -la\n" is the false-positive
case: either that test exists (must still write) or the rule
admits it cannot tell. Cover notes-then-write
(writeAfterLeadingComments) still succeeding.
