perPromptWorkingFiles — move latest* turn files into promptN/

Why:
The temp root holds both run state (messages.json, context,
auth) and per-turn working files named latest*. The loop is
serial, so latestModelResponse.txt is overwritten every
prompt. review_work then overwrites it again (ssa:815-823):
after a successful run the file is the review text, not
# complete. promptN/ already keeps HTTP and ask artifacts
for that turn (body.json, response.txt, userAnswer.txt).
The other latest* files are the same class: working files
for the current turn that KEEP_TEMP users want per prompt.

Do:
Rebind these in setup_per_prompt_log_folder the way
JSON_BODY_FILE is rebound (ssa:486-489). camelCase names,
no latest prefix:

  latestModelResponse.txt  -> promptN/modelResponse.txt
  latestScriptOutput.txt   -> promptN/scriptOutput.txt
  latestScriptExitCode.txt -> promptN/scriptExitCode.txt
  latestUserTurn.txt       -> promptN/userTurn.txt
  latestEditPayload.txt    -> promptN/editPayload.txt
  latestEditedBytes.txt    -> promptN/editedBytes.txt

Drop them from setup_temp_files. create_file_no_overwrite
in the new prompt folder (it is a new path each turn).
editPayload and editedBytes may wait until apply_edit_
request so a script-only turn does not grow empty files.
Write may extract through a file in promptN/ if that
matches the write path; do not add a third edit scratch.

Leave at the temp root: messages.json, messagesNext.json
(run transcript, mutated across turns), context.txt,
task.txt, url.txt, authHeader.txt, systemPrompt.txt.

prompt0/ then holds the bootstrap reply and its script
output (today it is often empty). The review POST keeps
its own prompt folder; modelResponse there is the
feedback. The last # complete stays in the previous
folder.

Do not collapse editPayload and editedBytes into one
file. jq still needs the SEARCH/REPLACE and the computed
bytes at the same time (fail-closed in-place edit). Do
not mkdir promptN on demand as a substitute for this
move; prompt1+ already mkdir's before curl. Do not add
a setting. Do not change what is fed to sh or written
to PATH.
