Why:
README Safety says the model gets your terminal, then ask-user and

AGENTS.md Design is wiring (ask tty, stdin to COMMAND, write -c).
Humans and agents both guess the rest (key file in the temp

Keep the existing ask bullets and the sandbox wrapper example.
Above or around them, state the model in short sentences:

- The model (and anything in the task, a context file, or output
  the model already ran) is untrusted. Default COMMAND is sh as
  you. Ask is the default gate; --no-ask removes it.
- Two layers: ask, then COMMAND. Combine both. Neither is a
  network jail by itself. Write/edit paths are your filesystem.
- The listing (and review, if that has landed) may show escaped
  CR/ESC/non-print; the sandbox file is raw. See
  sanitizeOutput / hardenAskListingUnicode.
- OPENAI_API_KEY is unset for child scripts. During the run it
  still lives in authHeader.txt under the temp folder, readable
  by the same user as default sh. Wipe on exit does not help a
  live script. The provider (OPENAI_URL) sees messages; a second
  review POST would see them again.
- Temp logs: default discard vs --keep-temp (or always-keep if
  that has landed). authHeader.txt is wiped either way when
  cleanup runs.
- Real isolation is COMMAND (user, timeout, netns) plus optional
  egress. Dummy-key injector is proxyDocs, not a sandbox.
