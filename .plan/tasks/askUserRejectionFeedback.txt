askUserRejectionFeedback — feedback after ask No

Why:
Ask No currently appends a fixed rejection ("User chose not to run
script. Try something else.") with exit 1. The model cannot tell why
the user refused.

Do:
When the user answers No, print this on stderr (ask UI, not stdout):

Give the AI model feedback about why you rejected, then press enter

Then a blank line, then read one line of feedback from /dev/tty
(same device as Y/N/Q). Include that line in the user turn in
messages.json so the next model prompt sees why the idea was
rejected. Keep the existing rejection text and exit 1; still do not
run the script. Empty feedback (just Enter) is ok. Yes and Quit are
unchanged. --no-ask is unchanged. Read failure from /dev/tty stays
fatal.

Log the feedback under promptN/ (for example userFeedback.txt),
same idea as userAnswer.txt.

Update the AGENTS.md ask-user No bullet. Keep -h short; no new flag.

Tests:
Ask needs /dev/tty, so --no-ask fake-curl stories cannot cover this.
If a pty is easy without extra tools, one story: No on a model
script, one feedback line, later Yes or done. Assert stderr has the
feedback prompt, the script did not run, stdout still has the
rejection text, and --keep-temp messages.json contains the feedback.
If a pty is not practical, still implement; note the gap.
