reviewWork — post-run model feedback on the transcript

Why:
After a run, the user only sees script output and a status line.
One more model call can read the transcript and say what would
have made the next run better (clearer task, fewer turns, a write
instead of a heredoc). Always on. No SSA_REVIEW_WORK. Settings
are env only.

Do not grow product ssa to match experiments/ssaWithReview
(fail-soft, review/ folder, feedback.txt, jq copy-and-swap of
the system turn). Prefer reuse over a parallel HTTP path.

Do:
After run_agent_loop returns (done or hit max), before
finish_agent_loop, append a user turn with append_json_message
(plain-text ask: what would make the next run better). Use the
already-capped transcript; do not grow the cap or restore dropped
turns. Increment PROMPT_COUNTER, call setup_per_prompt_log_folder,
then call_curl. Logs land in the next promptN/.

Do not run handle_model_response, ask, or the sandbox. Do not
append the review reply as a chat turn. Do not treat the reply as
a script, write, edit, or done marker. Skip review on die and on
SIGINT/SIGTERM.

Print "Feedback from model:" on stderr, then the reply through
sanitize_output (sanitizeOutput.txt; latestModelResponse.txt stays
raw), then a newline, then the existing status line. Stdout stays
script output only.

A failed review curl uses call_curl as today (harness failure).
Fail-soft (keep the task exit status) is the alternative if you
do not want a finished task to become exit 1.

Keep -h to one short clause. Update AGENTS.md stop / model /
settings. This is not a fifth reply shape and is not ask-No
feedback (askUserRejectionFeedback). After this lands in ssa,
the experiment is optional try-it; do not copy its thick
review_work.

Size:
About 15 lines to change in ssa (10–25). review_work, one main
call, a short user-turn string, one -h clause. No new setting.
Tests and AGENTS.md are extra, not in that count.

Tests:
Fake curl, SSA_NO_ASK=1. Story folder e.g. reviewWork.

- After # task complete: extra canned reply on stderr, not
  stdout; prefix Feedback from model:; status still
  "after N model prompts" with N the agent prompts only
- Extra curl is promptN+1 (SSA_KEEP_TEMP=1); messages.json has
  the review ask, not the review reply
- Hit max still reviews; exit stays 1 unless review curl dies
- Missing extra canned reply: curl dies (exit 1), not a
  silent skip
