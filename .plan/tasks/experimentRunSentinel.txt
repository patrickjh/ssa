Patch the fork enough to run the idea (details in
runOtherLanguages.txt):

- Closed dispatch: first action line must be `# run RUNNER`,
  `# write file:`, `# edit file:`, or `# complete`. Bare
  scripts are format errors. Payload is everything after
  the sentinel; leading notes are not fed to the runner.
- SSA_RUNNER default `sh`; space-separated names or paths;
  `command -v` at startup; die if missing or empty. The
  value is the whole list, not "sh plus extras."
- Append the live tokens to the system prompt as valid
  `# run` runners. One example (`# run sh`, or the first
  token if sh is not on the list). No extra full Python or
  Node samples.
- `# run sh`: `sh -n` the payload, then run. Other runners:
  write payload to a temp file, exec the list token on that
  file. No py_compile / node --check.
- Write and edit stay harness sh -c. They never go through
  the runner (python, node, or a jail). Ask still gates
  every run, write, and edit.

Drop SSA_SANDBOX_COMMAND in the fork (setting, check, stdin
to COMMAND, write/edit via COMMAND -c). Run turns exec the
listed token with no wrapper in between. Isolation the
caller still wants: list a jail as a runner
(`SSA_RUNNER=jail-sh` or a path), or wrap the whole
experiments/runSentinel/ssa process (container, sudo -u).
Do not restore a second env var in the fork. A wrapper
must take a script file (or stdin) like an interpreter,
not sh -c for writes. If you want the prompt to keep
saying `# run sh`, put the jail on PATH as `sh` so
`command -v sh` is the wrapper — that is environment, not
a new setting. Listing `/path/to/jail-sh` works but makes
the prompt uglier. SSA_RUNNER="sh python3" plus a jail is
several wrapper binaries, not one COMMAND that speaks
sh -c. That is the point of dropping the sandbox layer.
